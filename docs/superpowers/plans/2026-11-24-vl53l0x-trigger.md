# Wyzwalanie dalmierzem VL53L0X — plan

> Wykonanie: superpowers:executing-plans, zadania po kolei, commit po każdym.

**Cel:** Rejestrację wyzwala VL53L0X (odległość < próg), a nie próg drgań; nowa strona 4 z parametrami dalmierza.

**Architektura:** Czysta logika (`RangeTrigger`, `RangeUi`) w `include/` z testami PC. `RecorderCore` dostaje zewnętrzne wyzwolenie (`requestStart`) i czas nagrania zamiast detektora progu. `RangeTask` (core 1) odpytuje dalmierz tylko w stanie Armed; po wyzwoleniu zatrzymuje ranging do końca nagrania.

**Stos:** Arduino/PlatformIO, biblioteka `pololu/VL53L0X@1.3.1` (sekwencja inicjalizacji układu), `hal::I2cBus` (mutex).

**Spec:** `docs/superpowers/specs/2026-11-24-vl53l0x-trigger-design.md`

## Ograniczenia globalne
- Testy hosta: `g++ -std=c++17 -Wall -Wextra -Iinclude test/vibration_checks.cpp -o vc && ./vc` bez ostrzeżeń; kompilacja `pio run -e waveshare_vibration`.
- Teksty UI po polsku bez ogonków. Nieskomitowana praca nad `SwipeGuard` (pliki `include/SwipeGuard.h`, `TouchGestures.h`, część `main.cpp`/testów) nie jest częścią tej zmiany — commitować tylko własne zmiany (`git add -p` dla `main.cpp` i `test/vibration_checks.cpp`).
- Domyślne: próg 300 mm (30–1200, krok 10, od 500 krok 50), czas 5 s (1–30), pre-roll 1000 ms (0–1000, krok 100), tryb 1 = normalny (0 szybki 20 ms, 1 normalny 33 ms, 2 dokładny 200 ms). Potwierdzenie: 2 kolejne odczyty; histereza ponownego uzbrojenia 20 mm.

## Review Focus
- Odczyt „poza zasięgiem" (8190+, status ≠ 11) nie wyzwala i liczy się jako „daleko".
- Element stojący przed czujnikiem po końcu nagrania nie daje kolejnego pliku.
- Zmiana progu w trakcie czuwania działa od razu; brak dalmierza = brak wyzwalania i widoczny komunikat.
- Odmowa `sink.open` (brak karty) nie blokuje ponownego uzbrojenia ani nie zawiesza zatrzymanego rangingu.
